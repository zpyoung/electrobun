`BrowserView` is Electrobun's main-process wrapper around a native or CEF
webview. Every `BrowserWindow` creates one initial view, available as
`window.webview`. Create additional views when a window needs independently
positioned web content. In the native SDKs there is no view class:
`createWebview` returns a `u32` id and every operation is a `Core` call keyed
by that id.

## Constructor options

The constructor accepts `Partial<BrowserViewOptions>`.

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `windowId` | `number` | `0` | Native parent window ID. |
| `hostWebviewId` | `number` | none | Host view for an `<electrobun-webview>` child. |
| `url` | `string \| null` | `null` | URL to load. |
| `html` | `string \| null` | `null` | HTML string to load instead of `url`. |
| `preload` | `string \| null` | `null` | Inline JavaScript or a bundled `views://` script URL. |
| `viewsRoot` | `string \| null` | `null` | Override for the bundled views root. |
| `allowedProtocols` | `{ views?: boolean; appData?: boolean }` | `{ views: true, appData: false }` | Grant this webview access to Electrobun's filesystem-backed URL schemes. |
| `renderer` | `"native" \| "cef"` | Platform build default | Webview renderer. |
| `partition` | `string \| null` | `null` | Persistent storage/session partition. |
| `frame` | `{ x: number; y: number; width: number; height: number }` | `{ x: 0, y: 0, width: 800, height: 600 }` | Position inside the parent window. |
| `autoResize` | `boolean` | `true` | Resize with the parent window. |
| `rpc` | RPC instance | generated empty RPC | Typed main-process transport. |
| `navigationRules` | `string \| null` | `null` | Serialized navigation policy. |
| `sandbox` | `boolean` | `false` | Disable RPC for untrusted content. |
| `startTransparent` | `boolean` | `false` | Create the native layer transparent. |
| `startPassthrough` | `boolean` | `false` | Create with input passthrough enabled. |
| `spellCheck` | `boolean` | `false` | Enable native spell checking where supported. |
| `popupRequestId` | `number` | none | Adopt the popup from a `popup-request` event. See [Native page requests](#native-page-requests). |

<Aside type="note">
Use the DOM `<electrobun-webview>` element when the view's bounds should follow
an element in another webview. Construct `BrowserView` directly when the main
process owns its geometry.
</Aside>

## Loading and scripting

`allowedProtocols` controls filesystem access for this view. Enabling
`appData` permits reads from the app's `userData` directory through
`appdata://`, including after navigation to remote content. See
[Bundled and app-owned assets](/electrobun/apis/bundled-assets/) for examples
and protocol boundaries.

On Windows WebView2, unsafe, uppercase, Unicode, reserved, or over-80-character
partition names map to hashed profile directories. Safe lowercase ASCII names
use their original paths. For migration of existing profiles, see the
[Electrobun 2.0.2 migration notes](/electrobun/guides/changelog/v2-0-2/#windows-profiles-and-lifecycle).

```ts
import { BrowserWindow } from "electrobun/main";

const win = new BrowserWindow({
  title: "View controls",
  url: "views://mainview/index.html",
});
const view = win.webview;

view.loadURL("views://details/index.html");
view.loadHTML("<!doctype html><title>Inline content</title><h1>Hello</h1>");
view.executeJavascript("document.documentElement.dataset.host = 'electrobun'");
view.setNavigationRules(["views://details/*"]);

view.openDevTools();
view.closeDevTools();
view.toggleDevTools();

view.setPageZoom(1.25);
const zoom = view.getPageZoom();
const spellCheckChanged = view.setSpellCheck(true);

void zoom;
void spellCheckChanged;
```

`reloadIgnoringCache()` reloads the current page without using cached
responses and returns `false`, without reloading, when the renderer can't do
that. `supportsReloadIgnoringCache()` and `supportsLoadFailed()` report support
up front. Native WKWebView on macOS supports both; other renderers report
`false`.

`executeJavascript()` does not return the evaluated value. Use typed RPC when
the browser must return data to the main process.

Navigation and JavaScript evaluation are asynchronous native operations.
Wait for the target document's readiness (for example `dom-ready`, or an
application-level RPC readiness message) before evaluating code that depends
on it. `executeJavascript()` is not a readiness barrier or a promise of
execution: a view without a native browser/frame can discard the request.

While Linux CEF creates its browser, it retains the latest `loadURL()` or
`loadHTML()` request and starts that navigation when the browser is ready.
On macOS, WKWebView uses file-URL loading for local files. `getPageZoom()` reads
on the main thread after pending initialization and zoom changes.

## Session proxies

`Session.fromPartition(partition).setProxy()` sends every request from views
in that partition through a proxy: page loads, subresources, `fetch()` and
WebSockets. The proxy also resolves the hostnames, so an app can run a local
proxy that maps names such as `feature-a.localhost` to different local ports
without touching the system's DNS or proxy settings.

```ts
import { BrowserView, Session } from "electrobun/main";

if (Session.supportsProxy) {
  Session.fromPartition("persist:preview").setProxy({
    type: "http",
    host: "127.0.0.1",
    port: 8899,
    matchDomains: ["localhost"],
  });
}

const view = new BrowserView({
  url: "http://feature-a.localhost/",
  partition: "persist:preview",
});
```

| Field | Type | Purpose |
| --- | --- | --- |
| `type` | `"http" \| "socks5"` | `http` opens every connection, plain HTTP included, with `CONNECT`. |
| `host`, `port` | `string`, `number` | The proxy's address. |
| `matchDomains` | `string[]` | Only these domains and their subdomains use the proxy. |
| `excludedDomains` | `string[]` | These domains and their subdomains never use the proxy. |

The proxy applies to views already using the partition and to views created
later. Pass `null` to connect directly again. The setting lasts until the app
quits.

App Transport Security still applies to the URL. On macOS, a bundled app can
load plain `http` only from `localhost` and IP addresses unless its Info.plist
has an exception, so names like `feature-a.localhost` need an
`NSExceptionDomains` entry, which a `postBuild` hook can add.

Session proxies need macOS 14 or later and apply to the native WebKit
renderer. `Session.supportsProxy` is `false` on older macOS, Linux and
Windows, and `setProxy()` throws there rather than loading pages without the
proxy. CEF views don't use the session proxy.

## Host message queue diagnostics

`getHostMessageQueueStats()` reports the main
process's outgoing queue for this view. Use it to investigate a backlog when
sending bursts of RPC messages:

```ts
import { BrowserWindow } from "electrobun/main";

const win = new BrowserWindow({
  title: "Queue diagnostics",
  url: "views://mainview/index.html",
});

console.log(win.webview.getHostMessageQueueStats());
```

| Field | Meaning |
| --- | --- |
| `queuedMessages` | Messages and RPC responses currently waiting in the host queue. |
| `queuedBytes` | Serialized UTF-8 bytes currently queued. |
| `oldestMessageAgeMs` | Age of the oldest queued message, or `0` when empty. |
| `enqueuedMessages` | Total messages added to this view's host queue. |
| `drainedMessages` | Total messages removed from the queue for transport. |
| `peakQueuedMessages` | Highest recorded queued message count. |
| `peakQueuedBytes` | Highest recorded serialized byte count. |

These are host queue measurements. Byte counts are not retained heap usage,
and draining a message does not acknowledge delivery or rendering in the
WebView. Delivery uses byte-limited batches and yields between turns to keep
I/O responsive under load; the diagnostics do not impose a queue size limit.

## Events

Instance events cover navigation, readiness, and downloads. Event payloads are
currently typed as `unknown`.

```ts
import { BrowserView, BrowserWindow } from "electrobun/main";

const win = new BrowserWindow({
  title: "Events",
  url: "views://mainview/index.html",
});

win.webview.on("dom-ready", (event: unknown) => {
  console.log("DOM ready", event);
});
win.webview.on("did-navigate", (event: unknown) => {
  console.log("Navigation finished", event);
});
win.webview.on("download-completed", (event: unknown) => {
  console.log("Download complete", event);
});

const stopWatchingCreatedViews = BrowserView.on("created", (createdView) => {
  console.log("BrowserView created", createdView.id);
});
stopWatchingCreatedViews();
```

Supported instance event names are `will-navigate`, `did-navigate`,
`did-navigate-in-page`, `did-commit-navigation`, `dom-ready`,
`download-started`, `download-progress`, `download-completed`,
`download-failed`, `drop-source-paths`, `load-failed`, `close-requested`, and
the request events listed under [Native page requests](#native-page-requests).

`load-failed` carries `{ url, domain, code, description }` for a navigation
that failed before or after it committed. Depending on the WebKit version, a
navigation that is stopped or replaced by a newer one may report
`NSURLErrorDomain` code `-999`.

### Dropped file paths

When the user drops files from Finder or another app onto a view, the page gets
the usual DOM `drop` event, whose `File` objects carry names and contents but no
paths. `drop-source-paths` gives the main process the original absolute paths
of the same drop, in the order the page sees the files.

```ts
if (win.webview.supportsDropSourcePaths()) {
  win.webview.on("drop-source-paths", (event: unknown) => {
    const { paths } = (event as { data: { detail: { paths: string[] } } }).data
      .detail;
    console.log("Dropped from disk", paths);
  });
}
```

The event fires once per drop that the view accepted, and only when the drop
holds file URLs. Text, web links and file promises (for example a mail
attachment) don't produce it. A page can't send this event itself: it is only
accepted from the native wrapper.

`supportsDropSourcePaths()` returns `true` for the native renderer on macOS. It
returns `false` for CEF views and on Linux and Windows, where the event never
fires. Native SDKs receive the event through the webview `event` callback.


Download events carry an `id` that stays the same from `download-started`
through `download-completed` or `download-failed`. `download-progress` reports
`receivedBytes` and `totalBytes` (`-1` when the size is unknown) alongside the
percentage, and `download-failed` sets `cancelled: true` for a cancelled
download. `close-requested` fires when the page calls `window.close()`; the app
decides whether to remove the view.

## Native page requests

Some page actions wait for an answer: `alert()`, `confirm()` and `prompt()`,
HTTP authentication, an untrusted TLS certificate, where to save a download, a
popup, and a link to another application. By default the renderer answers them
itself. `setNativeRequestHandling()` hands the chosen kinds to the app instead.
Each one arrives as an event whose detail has a `requestId`, and the page stays
paused until the app calls `respondToNativeRequest()`.

```ts
import { BrowserView } from "electrobun/main";

const view = BrowserView.getById(webviewId)!;
const supported = view.setNativeRequestHandling(
  ["dialogs", "auth", "certificates", "downloads", "popups", "externalApps"],
  { timeoutMs: 120_000 },
);
if (!supported) console.log("Native page requests are unavailable here");

view.on("dialog-request", (event: any) => {
  const { requestId, type, message, origin } = event.data.detail;
  // Show your own UI naming `origin`, then answer:
  view.respondToNativeRequest(requestId, { accept: true, text: "Ada" });
});
view.on("native-request-expired", (event: any) => {
  // Close any UI still showing for event.data.detail.requestId.
});
```

| Kind | Event | Detail | Accepted with | Unanswered or declined |
| --- | --- | --- | --- | --- |
| `dialogs` | `dialog-request` | `type` (`alert`, `confirm`, `prompt`), `message`, `defaultText`, `origin`, `frameUrl`, `isMainFrame` | `{ accept: true, text }`; `text` is the `prompt()` result | `alert()` returns, `confirm()` returns `false`, `prompt()` returns `null` |
| `auth` | `auth-request` | `origin`, `host`, `port`, `protocol`, `realm`, `authenticationMethod`, `isProxy`, `previousFailureCount` | `{ accept: true, username, password }` | the challenge is cancelled |
| `certificates` | `certificate-request` | `origin`, `host`, `port`, `protocol`, `error` | `{ accept: true }` trusts the certificate for this challenge | the connection fails |
| `downloads` | `download-request` | `downloadId`, `url`, `suggestedFilename`, `mimeType`, `expectedBytes`, `origin` | `{ accept: true, path }` with an absolute path | the download is cancelled |
| `popups` | `popup-request` | `url`, `method`, `windowFeatures`, `origin` | create a `BrowserView` with `popupRequestId` | the popup closes before it loads |
| `externalApps` | `external-app-request` | `url`, `scheme`, `isUserGesture`, `origin` | `{ accept: true }` opens the URL with the system handler | nothing opens |

A request left unanswered for `timeoutMs` (120 seconds by default) takes the
right-hand column and emits `native-request-expired` with `reason: "timeout"`.
Removing the view does the same with `reason: "closed"`. Each request accepts
one answer: `respondToNativeRequest()` returns `false` for an unknown,
answered, expired, or other view's request.

Certificate requests only fire for certificates the system does not trust.
Credentials from an auth answer are used for that challenge only and are never
stored. A download path that already exists is numbered (`report (1).pdf`);
`download-started` reports the final path, and a relative path or a missing
directory cancels the download. Cancel an active download with
`cancelDownload(id)`.

External-app requests cover URLs the webview cannot load itself: schemes
WebKit does not handle and that have no registered scheme handler, such as
`mailto:` or `zoommtg:`. The navigation is cancelled immediately, so the page
stays where it was.

### Popups

The popup is created by the renderer from the opener's configuration, so
`window.opener`, the target window name, and a form's POST body all survive.
Its first navigation is held until the app adopts it:

```ts
import { BrowserView, BrowserWindow } from "electrobun/main";

view.on("popup-request", (event: any) => {
  const { requestId, url, windowFeatures } = event.data.detail;
  const popupWindow = new BrowserWindow({
    title: new URL(url).host,
    frame: { x: 200, y: 200, width: windowFeatures.width ?? 500, height: windowFeatures.height ?? 600 },
    html: "<!doctype html><body></body>",
  });
  const popup = new BrowserView({
    windowId: popupWindow.id,
    popupRequestId: requestId,
    sandbox: true,
    renderer: "native",
  });
  popup.on("close-requested", () => popupWindow.close());
});
```

Decline a popup with `respondToNativeRequest(requestId, { accept: false })`.
The popup shares the opener's partition. A popup from a sandboxed opener can
only be adopted by a sandboxed view; any other view is created empty instead.
An adopted popup starts with native requests off, like any new view.

<Aside type="caution">
Native page requests are available for macOS native WKWebView.
`setNativeRequestHandling()` returns `false` for CEF and for WebView2 and
WebKitGTK, and those renderers keep their default behavior.
`beforeunload` prompts are not included: WKWebView has no public API for them.
</Aside>

## Typed RPC

Define the shared schema in a module imported by both contexts. The main process
uses `BrowserView.defineRPC`; the browser uses `Electroview.defineRPC`.

```ts
import {
  BrowserView,
  BrowserWindow,
  type RPCSchema,
} from "electrobun/main";

export type AppRPC = {
  bun: RPCSchema<{
    requests: {
      greet: {
        params: { name: string };
        response: { message: string };
      };
    };
    messages: {};
  }>;
  webview: RPCSchema<{
    requests: {};
    messages: {
      statusChanged: { online: boolean };
    };
  }>;
};

const rpc = BrowserView.defineRPC<AppRPC>({
  handlers: {
    requests: {
      greet: ({ name }) => ({ message: `Hello, ${name}` }),
    },
    messages: {},
  },
});

const win = new BrowserWindow({
  title: "Typed RPC",
  url: "views://mainview/index.html",
  rpc,
});

rpc.send.statusChanged({ online: true });
void win;
```

The browser-side half is documented under
[Electroview](/electrobun/apis/browser/electroview-class/).

## Lookup, adoption, and removal

```ts
import { BrowserView, BrowserWindow } from "electrobun/main";

const win = new BrowserWindow({
  title: "View ownership",
  url: "views://mainview/index.html",
});

const existing = BrowserView.getById(win.webview.id);
const allViews = BrowserView.getAll();

if (existing) {
  const wrapped = BrowserView.ensureWrapped(existing.id, {
    windowId: win.id,
  });
  const adopted = BrowserView.adoptExisting(existing.id, {
    windowId: win.id,
  });
  void wrapped;
  void adopted;
}

void allViews;
```

`ensureWrapped()` and `adoptExisting()` are advanced APIs for native views that
already exist. Calling `remove()` destroys a view and disconnects its RPC
transport; repeated calls are safe.
